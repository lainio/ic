## 1. Decision summary

Recommend AES-256-GCM records, HKDF-SHA-256 purpose separation, and HMAC-SHA-256 equality indexes. This protects logical keys/values and detects tampering and relocation across expected contexts. It does not provide authorization, metadata secrecy, deletion protection, or replay protection. Approved requirements come from `docs/architecture/managed-storage.md:31`; details below are proposals refining `docs/architecture/managed-storage-implementation-plan.md:85`, not prior approvals. D2 needs owner acceptance of format, bounds, and probabilistic nonces, plus the OPEN D4 lifetime-budget guarantee. D3 needs owner acceptance of leakage, collisions, and layout. D4 provider/authorization/rotation and D5 backup/restore remain unapproved. V19 forbids restoring consumed authority (`S/docs/contracts/IntroTree_StateSemantics_Contract.md:493`); authenticated bytes cannot establish safe recovery.

## 2. D2

**Proposed encoding:** unsigned integers are big-endian; concatenation is `||`; `LP(x)=u32(len(x))||x`. Wire order:

| Field | Bytes | Rule |
|---|---:|---|
| Version, suite | 1, 1 | Both 1; suite fixes all three primitives |
| KeyID | 16 | Immutable public identifier I |
| Body length B | 4 | B=28+P |
| Nonce | 12 | Public, generated by AEAD |
| Ciphertext | P | Encrypted plaintext below |
| Tag | 16 | Full GCM tag |

First 22 bytes form public header H. Plaintext=`LP(logicalKey)||LP(value)`; key 1–4096 bytes, value may be empty, 9≤P≤1,048,576. Envelope length must equal 22+B, maximum 1,048,626. Reject truncation, trailing bytes, overflow, invalid lengths, unknown version/suite/KeyID, mismatched expected KeyID, or authentication failure; never fallback/create replacement state. Bound allocations before decryption; parse plaintext only after authentication.

Context `C=LP(VaultID)||u32(segmentCount)||LP(segment1)||…`. VaultID V is 16 bytes; at most 64 segments, each 1–1024 bytes; C≤16,384 bytes. Root has zero segments; an empty segment is invalid. Slashes are literal; no normalization. AAD=`LP("ms/v1/record")||LP(H)||LP(C)||LP(token)`. V/path and expected token come from caller scope/location, never the envelope; swapping header and ciphertext cannot substitute expected context.

Provision independent uniformly random 32-byte secrets S per vault/key generation, externally; no global/default key, raw password, or plaintext adjacent secret. I identifies an immutable secret generation, not authorization. Derive KE/KI using `hkdf.Key(sha256.New,S,[]byte("ms/v1/hkdf"),string(info),32)`; info=`LP(label)||LP(V)||LP(I)`, labels `ms/v1/enc` and `ms/v1/idx`. These are vault-generation keys, shared across its namespaces.

**Source facts:** module minimum is Go 1.24.0 (`go.mod:3`); HKDF and random-nonce GCM exist there (`G/api/go1.24.txt:8`, `:13`); derivation signature: `G/src/crypto/hkdf/hkdf.go:59`. Use `aes.NewCipher(KE)`, then `cipher.NewGCMWithRandomNonce`; `Seal(nil,nil,plaintext,AAD)` returns nonce+ciphertext+tag; `Open(nil,nil,body,AAD)` extracts nonce. NonceSize=0, Overhead=28 (`G/src/crypto/cipher/gcm.go:79`). Codec stores that body unchanged. Internal randomness reaches fatal entropy handling (`G/src/crypto/internal/fips140/aes/gcm/gcm_nonces.go:42`, `G/src/crypto/internal/fips140/drbg/rand.go:43`, `G/src/crypto/internal/sysrand/rand.go:30`). No recoverable entropy error or injectable reader exists in this API. Replace the legacy unversioned/nil-AAD wrapper (`/home/parallels/go/src/github.com/findy-network/findy-common-go/crypto/crypto.go:50`).

**Proposed refinement for approval:** cap lifetime seals at q=2^24 per actual KE, across all namespaces/files/processes/reopens/restores. Assuming uniform independent 96-bit nonces, collision probability ≤q(q−1)/2^97<2^-49, not guaranteed uniqueness. Every seal burns usage before AEAD; aborts/failed commits never refund it.

**OPEN D4** (`docs/architecture/managed-storage-implementation-plan.md:127`): recommend external, rollback-resistant accounting issuing nonoverlapping, irrevocably precharged allowances outside engine locks. C3 can require a nonnil spend gate and enforce local allowance exhaustion; it cannot prove global accounting. Neither process-only nor restorable-database counters suffice. Missing/uncertain/exhausted allowance disables sealing; reopening/restoring cannot replenish it. Lost unused allowances are forfeited; allocations cannot be replayed. Provider discovery, unlock, hardware adapters, rotation, and restoring accounting require later design.

## 3. D3

Token=`HMAC-SHA-256(KI,LP("ms/v1/lookup")||LP(C)||LP(I)||LP(logicalKey))`, stored as all 32 raw bytes, without truncation/hex. After decryption, recompute and compare using `hmac.Equal` (`G/src/crypto/hmac/hmac.go:59`). Get/replacement/Delete also compare authenticated logicalKey byte-for-byte with requested key. An existing token with a different authenticated key returns collision/conflict even if HMAC verification succeeds; never overwrite. Seal computes its own token.

Absence comes only from engine found=false; empty values remain present. Each rejects tokens not exactly 32 bytes, decrypts direct records, verifies tokens, returns owned keys/values, and stops on failure; order unspecified. Existing namespace/iteration work: `storage/internal/engine/engine.go:45`, `storage/internal/engine/namespace_test.go:283`.

Propose per-node reserved engine children: byte 01 records, 02 child namespaces, 03 metadata; user segment names live beneath 02, separately from tokens. C4 preserves logical name conflicts. Layout wiring awaits D4; no engine change.

Visible: VaultIDs, namespace names/tree, KeyIDs, header fields, nonces/tags, tokens, counts, aggregate key/value lengths, equality/access patterns and snapshot changes. No range queries, access control, or anti-replay follows from HMAC.

## 4. Private API and acceptance

Private `storage/internal/record` sketch; scope binds V/I and spend gate:

```go
Derive(secret []byte, v, id [16]byte, spend func() error) (*Scope, error)
(*Scope) Token(path [][]byte, key []byte) ([32]byte, error)
(*Scope) Seal(path [][]byte, key, value []byte) ([]byte, error)
(*Scope) Open(path [][]byte, token [32]byte, wantKey, record []byte) (key, value []byte, err error)
(*Scope) Clear()
```

Nil wantKey selects iteration; otherwise require a nonempty key and compare exactly.

Spend consumes one precharged KE allowance on success; errors prevent AEAD; no provider calls occur inside it. C4 supplies authorized V/I mapping; codec never discovers keys from headers. Copy retained inputs; own outputs. Clear invalidates scope, clears owned key buffers best-effort, and drops AEAD references; Go cannot guarantee schedule/GC erasure. No plaintext on any failure. Errors distinguish input/format, unsupported identifiers, authentication, collision, and budget denial. No transactions, wallets, files, goroutines, or providers inside codec. Preserve err2/try, specific assert helpers/PushTester (`storage/AGENTS.md:3`), and glog without secrets/plaintext/logical-key logs.

Proposed adapter tests: round trips/empty values; independently fixed derivation/token vectors; segment ambiguity; tampered header/nonce/tag/ciphertext; wrong vault/path/secret/logical-key/token; unknown identifiers; malformed/oversized inputs; owned buffers; injected budget failures/exhaustion/no refunds across shared scopes. Test the exact-key collision guard directly, without finding HMAC collisions. C4 separately validates global allowance non-reissuance across restores. No entropy-error injection or randomness weakening; no nonce-uniqueness or primitive-security proof. C3 split after approval: encoding/derivation vectors, then AEAD/budget adapter, then token validation.

Validation: source inspection only; tests not run. Owner-reported passing tests are separate evidence.

D2 **conditional; D4 budget OPEN**. D3 **ready for owner review**, subject to D2/D4 dependencies. C3 needs separate authorization; production sealing depends on D4 enforcement. No implementation approval granted.
